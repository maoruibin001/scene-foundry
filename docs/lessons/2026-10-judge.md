# 灰模空间评委：经验总结（2026-10-27 至 10-29）

本文是写给后续开发者的复盘，回答三个问题：评委这件事最后做成了什么，中途得出过哪些错误结论，以及今后怎样避免同类错误。
数据与脚本见 `workbench/bench/gt`（真值基准）和 `workbench/src/geometry/object3d-gate.ts`（新评委）。

## 1. 最终可信的结论

| 评委 | 场景级 ρ（对比可见物体的位置误差，18 个室内场景） | 已知变差对排序 | 说明 |
|---|---|---|---|
| VLM 空间评委（gpt-6-astra） | +0.33 [−0.25, +0.72] | 8/12 | 最弱；重复打分稳定（极差 ≤ 0.1），但看不出旋转、缩放错误 |
| 2D 地标残差 | +0.61 [+0.20, +0.85] | 9/12（室内） | 在场景级有效 |
| 整图深度一致度 | +0.68 [+0.30, +0.88] | — | 在场景级有效 |
| **object3d（逐地标三维）** | **+0.73 [+0.34, +0.93]** | **11/12** | 逐物体 ρ 0.84 [0.74, 0.90]；能抓住"推远并放大、参考视角里看不出差别"的错误 |

- 在场景级，基于测量的三种评委都有效。object3d 最高，但领先幅度在统计上不显著。
- object3d 的实际优势有三点：逐物体精度高；对已知变差排序更准；接入门禁后，修复的改善得到了真值证实。最难的场景真值误差从 0.77 降到 0.23。
- 管线把门禁换成 object3d，这个决定在修正后的证据下仍然成立。

## 2. 错误结论"VLM 评委在三维正确性上是反向的"是怎么来的

| 时间 | 做了什么 | 当时的结论 | 实际问题 |
|---|---|---|---|
| 10-27 | VLM 分数对比"锚定召回" | ρ −0.31，"评委是反的" | 区间 [−0.69, +0.27] 包含 0，本来就不显著；尺子也有缺陷 |
| 10-27 | 2D 残差对比召回 | 先报 +0.43，后改为 −0.43，"也是反的" | 第一次把符号看反了；尺子仍是同一把有缺陷的召回 |
| 10-27 | 整图深度对比召回 | ρ ≈ 0.1，"没有信号" | 尺子问题，不是工具问题 |
| 10-29 | 建立不依赖标签的逐物体真值，用来验证 object3d | object3d 通过 | **新尺子只用来验证新评委，旧评委没有用它重测** |
| 10-29 | 基准 v5 剔除物体太少的场景后，中心误差 ρ +0.62 显著 | "反向得到加强" | 中心误差只在已匹配的物体上计算，存在选择偏差，仍然是坏尺子 |
| 10-29 | 以"反向"为核心观点写论文初稿和 PPT | — | 结论建立在上面这些问题之上 |
| 10-29 | 负责人要求发表前先确认 | 用新尺子重测所有评委：VLM +0.33，2D +0.61，深度 +0.68 | **撤回"反向"结论** |

### 根因
1. **尺子坏了。** 按标签匹配的召回和匹配物体的中心误差，在物体少的场景上会失真，还存在选择偏差。最极端的 ai_053_007 真值只有 4 个物体，任何结果的召回都接近 0。
2. **比较时用的不是同一把尺子。** 新评委用好尺子验证，旧评委用坏尺子验证，再拿两者做对比。这是最关键的错误。
3. **不显著的结果被当成了方向性结论。** 区间包含 0，就只能说"没有证据表明相关"，不能说"相关是反的"。
4. **漂亮的机制解释让人停止了检查。** "投影一致的三维错误"在原理上成立，在个例上也确实存在，但它不能证明总体相关是负的。
5. **一次符号错误。**

## 3. 今后的规则

1. **先验证尺子，再验证评委。** 优先用逐物体、不依赖标签的真值；场景级召回这类粗指标只作辅助。
2. **所有候选必须用同一把尺子比较。** 换了尺子，就把之前所有相关结论全部重算一遍，包括已经"定论"的。
3. **区间包含 0 时，不下方向性结论。** 汇报时同时给出区间和样本量。
4. **机制解释要用单独的实验验证。** 例如"推远并放大"这类人为变体，而不是只用来解释已有数据。
5. **对外发布前做一次"反证检查"。** 主动找最可能推翻结论的检验，并且在发布前完成。
6. **否掉一个工具之前，先换粒度、换目标再试一次。** 整图深度在场景级其实有效；这次被否掉，是因为用错了尺子。
7. **能程序化验证的先程序化验证，必须用订阅时控制规模。** 本轮修复的管线缺陷，全部先用已录数据回放确认。

## 4. 实跑中暴露的管线缺陷（均已修复）

- 灰模预览被重复绑定，测量锁定不幂等，导致每轮修复预览失败（92e99d9）。
- 修复模型去改已锁定的机位，改动无效（2f77795）。
- 不可见地标的反馈没有位置信息（9673571）。
- 修复中途失败后无法恢复（6a612a7）。
- 机位净空检查查的是模型给的机位，不是锁定后的机位（2048b36）。
- 成品修复派生出的副本被再次绑定，预览回执始终对不上（56f9a6e）。
- 基准中真值物体少于 8 个的场景不再计入物体统计（gt-scene-score-v5，322ced7）。

共同的教训：评委不可信时，管线缺陷会被掩盖，因为反正分数也说明不了什么；换成可信的评委后，这些缺陷才会一个个暴露出来。
