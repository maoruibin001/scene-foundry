# 系统性稳定性方案（方向调整）

日期：2026-10-15。目标调整为 **A：高概率产出合格场景**，用**系统方法**提升稳定性，不再追未校准的质量分，也不在本轮追高保真原图还原。

## 1. 把"稳定性"定义成可测的数字

稳定性 = **P(一次运行 → 到达合格闸门)**，以及它的方差。合格闸门是机械的通过/失败（灰模 3.5/3/0.6、basic70、运行硬检查），**不需要人工校准**（这和"质量公不公正"是两回事）。所以稳定性现在就能可信地量。

度量方法：**稳定性测量台（harness）**——固定一组代表性输入 × 每个跑 N 次（走网页路径、隔离 DATA），自动统计：
- 总体通过率；
- **逐阶段到达/通过率**（plan / observe / space / graybox / assets / runtime / judge / gate）；
- **失败模式直方图**（见下）；
- 分数方差。

一个可重复的数字 + 失败分布，就是我们的"温度计"。每个改动的验收标准 = **在同一测量台上通过率显著上升**，否则不合入。

## 2. 失败模式分类（来自本会话的真实数据，不是臆测）

| 代号 | 失败模式 | 证据 | 性质 |
|---|---|---|---|
| **M1** | 灰模初始规划波动（约 50% 卡在灰模） | 游乐场首轮 2.1 vs 2.2 决定成败；A/B 里两边各约半数灰模挂 | 方差（最大头） |
| **M2** | 模型调用/供应商失败（超时、PROVIDER_RECOVERY_EXHAUSTED） | r9/r10 全部阻塞、中转断流 3h、本机断网 | 基础设施 |
| **M3** | 管线脆弱：契约指纹不同步、评审复开失败 | 遮挡契约 bug、d0ddfe6 的 jointFit 同类 | 自造脆弱性 |
| **M4** | 治理/预算过早停：相同输入共享改进线程被 noGain 掐、IMPROVEMENT_STOPPED | base3/cand3 被掐、noGain 误伤 | 治理 |
| **M5** | 提示/输入敏感：改写提示灰模更易挂 | 3/4 改写变体灰模挂 | 鲁棒性 |
| **M6** | 下游失败：材质规划超时、资产未齐 | 赛博朋克材质两次超时、多次 partial | 下游执行 |

## 3. 系统程序（测量驱动，逐个消灭失败模式）

1. **建测量台**，跑**基线**：当前通过率 + 失败模式分布。没有这个基线，后面全是盲调。
2. **按占比从大到小逐个修**，每个都用测量台验收通过率增量：
   - **M1**：多初始规划择优（`graybox-multiplan-v1`，**已实现、正在验证**）——按概率把灰模通过率 ~50%→~85%+。这是最大头。
   - **M2**：供应商恢复鲁棒性（重试/退避/断点续跑的覆盖与可观测）。
   - **M3**：契约/复开一致性做成**不可能不同步**（把分散在两处的 flag 收敛到一处），加回归测试锁死。
   - **M4**：治理隔离（独立线程、noGain 不误伤择优/独立样本）——multiplan 的盐机制已是一例。
   - **M5/M6**：输入鲁棒性与下游执行（分区材质检查点等）按测量台数据决定是否值得。
3. **再测**，看通过率曲线系统性上移；稳定到目标（比如简单场景 ≥90%）后，再谈更难的输入。

## 4. 纪律（这次必须守住）

- 分支先行；**只有测量台上通过率实测上升才合入**；不盲合、不追未校准的分。
- 每个失败模式的修复都配回归测试，防止 M3 这类"自造脆弱性"复发。
- 测量用隔离 DATA/端口，不碰共享服务与历史数据；额度按授权。

## 5. 立即要做的

1. **建稳定性测量台**（固定输入集 × N 次，自动出通过率 + 逐阶段 + 失败直方图）——这是"系统性"的地基。
2. 把**正在跑的 multiplan 实验**作为 M1 的第一组数据接进来（它本身就是一次小测量）。
3. 跑**基线**（multiplan 关），得到"修前"通过率，与 multiplan（修后）对比。

先建台 + 出基线，之后每个失败模式的修复都对着这个台验收。这才是"系统性解决稳定性"，不是再堆一个单点修补。
