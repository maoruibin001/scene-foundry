# 规格场景三模型原图视觉评审

新建规格场景与“评审现有场景”采用本地订阅的 `codex1`、`codex2`、`codex3`。其他生成节点保留原模型设置；历史 CBC 报告保留，不参加新一轮联合选优。此实现针对规格场景视觉节点，不改变普通场景的其他评分协议。

三路读取同一份原图字节、顺序和 `spec-style-judge-v2` 协议，分别独立回答。管线记录启动器 SHA、实际 CLI 模型/推理强度/供应商/只读沙箱回执；不缩图、不转 JPEG，不将账号默认模型误认成启动器实际模型。启动器带 --yolo，评审适配器只读取并冻结其模型选择，由同一官方订阅 CLI 显式 --sandbox read-only 执行；同时保留选择启动器与实际可执行文件的双份 SHA。不符合已审计的简单订阅启动器契约时拒绝执行，不回退 CBC 或其他模型。

采用最高有效整体分，并保留该评委整份六维报告，不跨模型拼维度。原 `overall >= 70`、每维 `>= 2`、`verdict != mismatch` 条件保留；三路未全部得到有效报告时标记 partial，不能通过完整联合评审。运行硬检查、缺资产和人工认可独立，视觉分不覆盖它们。最高分是择优策略，不代表模型共识或场景改进。

每轮独立保存：

- `input.json`：原图/实际发送文件 SHA、字节数，提示词与 Schema SHA。
- `request.json`：实际公共评审提示词和输入上下文。
- `codex1/`、`codex2/`、`codex3/`：输入回执、进程日志与 PID/时间、原始回答、解析报告和路由；失败也单独保留，不填占位分。
- `panel.json`：三路结果、最高分及来源、中位数、范围、有效数、选优策略。
- `joint-feedback.json`：所有有效评委反馈，包括低分和分歧，供受控外观续修使用。

正常 UI 的联合评审卡片展示全部模型、六维评分、耗时、CLI 已报告 tokens 和证据链接，保留历次评审入口。未提供计费回执时，单次金额保持未知，不能将订阅调用说成零成本。评委准确度需要用户独立判断作为参照，不能用“谁分高”代替“谁准确”。

## 联合反馈后的修订

已有外观修订入口会收到包含 jointFeedback 的评审对象，同时考虑所有有效评委；不只迎合最高分。矛盾建议须按冻结规格和真实像素取舍，规格外或无证据建议不执行。继续保持几何、机位、交互冻结及既有修订/预算门禁，不自动新增修订轮次。

一次“三路初评 → 一次修订 → 三路终评”需要 7 次模型调用和一次额外真实采集（不含路由预检）。修订后仍独立看新截图，保留前后构建、评分与全部失败。不能仅凭此机制保证提升效果。

本轮用户另行批准最多 6 次调用：三路小图路由预检 + 同一保留场景的三路正式评审。未包含自动修订或第二轮采集/复评。既有失败场景上的重评属于诊断，不提升其运行/交付状态。
