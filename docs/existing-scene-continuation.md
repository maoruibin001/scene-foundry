# Existing scene continuation

An existing Engine project is a source library, not a request to rebuild the scene from concept images. `scripts/adopt-engine-pack.ts` converts its selected authored scene pack into the ordinary `scene-spec-v1` input. Source mesh payloads are sealed by full metadata/binary SHA256, material bindings and original placement are retained, and camera/native environment values are carried through separately from model staging. No authoring result is uploaded automatically.

The operator admits one `PIPELINE_SOURCE_ASSET_ROOT`. Uploaded specifications can reference only relative regular files inside it; path traversal and escaping symlinks are rejected. Missing/changed/invalid sources fail rather than silently becoming proxies. Sequential and parallel exports share this source path and always seal imported geometry into cooked output, including when generator precooking is disabled. The intake is an asset reuse step, not a claim that historical hand-authored assets were generated by the pipeline.

`continueSpec` requires the immutable previous spec digest and a reasoned revision. The receipt records base/result digests, touched IDs, retained objects and retained source hashes. Frozen placement cannot be moved or removed. `replaceGeometry` is an explicit geometry-only revision that retains the object's placement and previous input in the revision receipt. Its generator and optional material bindings are visible. The normal `POST /api/spec-jobs/:id/continue` route preserves the source job/root and rejects duplicate in-flight continuations. Candidate revisions must pass ordinary Engine/visual checks before they are adopted into an existing game. The original project's scripts, interactions and files are never overwritten by an exported template.

`GEN-ENTRY-01` supports independently omitting a second vestibule and a local origin for a baked world-space source replacement. These are general generator parameters, not project-name branches. A generated open gate is a static scene candidate; it does not imply door animation or gameplay wiring has passed.

`performance-audit.json` is an offline inventory of mesh triangles and instances. It names candidates for player-distance LOD/normal baking, but does not assert GPU timing, FPS, executed draw counts or optimization. High-to-low normal baking and automatically selected LOD are not implemented by this change. Their production stage must bind source/output hashes and UV/cage/tangent conventions, preserve silhouettes, use matched actual runtime/viewports and compare images before adoption.
