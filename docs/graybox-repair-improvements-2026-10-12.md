# 普通场景灰模修复改造说明（2026-10-10 至 10-12）

本文说明普通场景（非体素）灰模阶段做了哪些改造、每项为什么能提高合格率，以及真实网页验证的结果和尚未证明的部分。代码范围是 main 上 `44e52df..c687070`，共 16 个提交，已于 2026-10-12 推送。

## 合格标准与原来的问题

灰模阶段要求空间分 ≥3.5、关键关系分 ≥3、置信度 ≥0.6，且多机位联合拟合（jointFit）不能退步。

流程是“生成灰模 → 真实 Engine 预览 → 对照原图评审 → 修复 → 再预览”的循环。每一轮修复只有分数确实提高才会被采用，连续两轮没有有效提升（`noGain:2`，有效提升至少 0.1 分）时任务停止。

改造前，市场等场景的空间分常停在 2.8–3.2，过不了 3.5。逐轮查看修复产物后发现，瓶颈不在于模型画不出来，而在于这个循环本身：

1. **测不到。** 关键地标共用实例时，评审无法分清哪个实例属于哪个地标，只能标为 unverified，这些行既不能算对齐，也给不了修复方向。
2. **改不了。** 模板边界在规划时冻结，连续的立面或屋顶被截断后，修复无法补全。
3. **好的候选被丢弃，或者整个任务被中止。** 选择规则和联合拟合规则过严。一轮修复只要“关掉两处阻断、新开一处临界阻断”就会被整体丢弃；联合拟合中一行轻微退步，就会让整个任务失败。
4. **调不准。** 模型手工微调位置，每个机位的平均边缘残差只能改善约 0.01，几轮下来累计不到 0.1 分的有效提升，于是触发 noGain 停止。

每解决一层，瓶颈就移到下一层。下面的改造按这个顺序进行。

## 改造清单

所有放宽都按任务策略开关生效：新建的普通任务会在 `runner.ts` 的 `createJob` 中写入 `job.*Policy` 字段，历史任务按原规则重放，结果不变。体素任务不受影响。

### 一、先让关键关系可测量

| 提交 | 改动 | 为什么有效 |
|---|---|---|
| 1d7cda9 | graybox-space-preview-v13 引入 joint-fit-v1。以下任一情况发生，候选都不能被最终选中：任一参考机位的平均边缘残差变差超过 0.002；任一关键目标变差超过 0.01；关键目标变得不可见；已测的关键覆盖范围缩小 | 防止模型用“修好一个机位、弄坏另一个机位”的方式刷分。被选中的候选在所有原图视角下都没有变差 |
| ce6f570 | reference composition v4：只测量各地标独占的实例；同一机位有重复框时，按可见质心分配 | 共用绑定的关键地标原本只能标为 unverified，现在可以按实际像素测量 |
| d712c45 | 新规划时，每个关键地标在每个机位上至少要有一个独占实例（策略 `critical-view-exclusive-v1`），所有冲突一次性报出 | 从规划阶段就保证每个关键地标可测，不必等到修复时才发现测不到 |
| ea02919, 5d45fd8 | reference composition v5：几个地标只共用同一个实例时，把它的各个可见部件分配到对应的框；评审和修复都使用部件级测量 | 剩余的 unverified 行也能被测量，修复有了明确的残差目标 |

**原理：** 修复循环只能优化测得到的东西。unverified 行永远不算对齐，也无法指导修改。把这些行变成可测量的行，是后面所有提升的前提。

### 二、让修复有空间改

| 提交 | 改动 | 为什么有效 |
|---|---|---|
| 5ca59db `template-bounds-v1` | 修复补丁最多可以扩大 2 个已有模板的边界：只增不减，每个轴的跨度不超过原来的 2 倍。扩大后，部件仍按新边界重新校验 | 规划时定得过小的立面、屋顶，原来在修复阶段无法延伸，关键关系卡在约 3.0。地铁场景（r3）一轮修复就从 3.0 升到 3.7 |
| 05bc4de | 灰模输出 schema 写明编译器要求的部件 id 格式；预检查一次列出所有不合法或重复的 id | 地铁曾因部件 id 写成 `T16_推断_侧背墙` 被编译器拒绝，而纠正提示只给出第一个错误，导致任务失败。现在一次就能纠正全部 |

### 三、不再丢弃真正的改进

| 提交 | 改动 | 为什么有效 |
|---|---|---|
| 11b6051 `net-closure-v1` | 同时满足以下条件的修复候选，会成为下一轮修复的基础，而不是被丢弃：关掉的关键阻断比新开的多，空间分提高，且新开的阻断都在关键阈值 0.5 分以内（临界） | 市场场景某一轮关掉 2 处阻断、新开 1 处临界阻断，原来整轮被丢弃 |
| c687070 `net-closure-v2` | 关掉的和新开的一样多（至少各 1 处）时，只要新开的都是临界阻断且分数提高，也接受 | 市场 r8 第 4 轮以 3.2 分超过了 3.1 分的基础：关掉 `elevated_junction`，新开临界的 `visible_branch_connection`（2.5 分）。v1 要求关掉的必须多于新开的，于是丢弃了这个更好的候选并记为“无进展”，加上第 3 轮也没有进展，任务因 noGain 停止 |
| cddeaf0 `joint-fit-net-v1` | 某个机位的已测目标平均改善至少 0.01 时，允许其中一行关键目标退步不超过 0.03。一轮修复的所有真实预览都被拦下时，只记为一次无进展，并把拒绝原因反馈给下一轮，而不是让任务失败 | 市场 r4 从 3.0 升到 3.2 后，第 2 轮出现 `GRAYBOX_JOINT_FIT_REGRESSION`：每张预览都有一行关键目标退步 0.025，而该机位均值改善了 0.023，结果整个任务被判失败 |
| d0ddfe6 | 评审后几何交接时，重新打开预览审计会带上 `jointFitNet` 标记 | 修复前，joint-fit-net-v1 任务的契约摘要永远对不上，第一轮修复后灰模阶段必然失败 |

**原理：** 修复循环本质上是逐轮爬坡。只要“净进步”的一步被当作“无进步”，或者一行小退步就中止整个任务，循环就会在离合格线一步之遥时停下。这些改动只接受同时满足以下条件的候选：分数提高，新增问题处于临界范围，整体残差在改善。仍然被拒绝的情况包括：关键阻断净增加、分数不升、新增阻断低于临界范围、出现联合拟合的硬性退步。

### 四、让小幅位置调整调得准

| 提交 | 改动 | 为什么有效 |
|---|---|---|
| 8bbbefd `graybox-space-fit-v1` | 新增 `fit_graybox_space` 工具。模型先写出依据原图的完整补丁，再列出最多 6 个相关实例和最多 2 个参考机位；程序用零 Engine 的几何测量，对实例位置、统一缩放（来源的 0.5–2 倍）以及机位位置、朝向和 fov 做有界坐标下降，每个被采用的候选都必须通过 jointFit。每轮最多 2 次拟合、合计 320 次测量、每次 60 秒，失败与重试都计入，不会重置。结果只是预测，必须交给 `preview_graybox_space` 做真实预览，并通过独立原图评审才能被选中 | 离线实验中，这个拟合把一个机位的残差从 0.118 降到 0.080，而模型手工调整每个机位只能改善约 0.01。它把模型擅长的事情（判断该改什么）和程序擅长的事情（精确数值优化）分开 |

## 尚未证明与已知限制

- **c687070（net-closure-v2）还没有经过真实生成验证。** 它针对的正是市场 r8 的失败。市场要再通过 1–2 次，才能说三个场景都能高概率合格。
- 市场的 `open_far_end` 关系一直停在 2.5 分。远端只有一块平板，结构过于简单，单靠位置拟合提高有限。
- 在市场场景上，数值拟合每次都会用满 60 秒的时间预算，每次测量约 0.4–0.6 秒，每次调用只能把目标值降低约 0.01–0.02。
- 空间分来自模型评审和矩形残差，不是像素分割，也不等于原图像素级还原。

## 复现与回归

- 测试：`cd workbench && PIPELINE_DATA_DIR=<含 reconstruction-env 与 material-catalog 的临时目录> bun test ./src`。合入前 1289 个测试全部通过。
- 每次网页 E2E 都使用独立的 DATA 目录、模型账本和验证控制文件。验证控制文件中的 `model` 必须与任务的 `modelSettings.model` 一致，否则创建按钮会被锁定。
- 修复循环停在合格线以下时，先看对应轮次的 `gate.json` 中的 `selection.reason`、`space-repair-N/scene-space-contract-error.txt` 和预览审计，再判断是不是几何表达能力不够。
